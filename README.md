# LipatoS — Уникальные предметы Айндора

Один модуль для Foundry VTT v14 и D&D 5e 6.x. Для работы ремня требуется включённый **libWrapper**.

- **Багряная мантия:** запоминает заклинания 1–3 уровня, повторяет за заряд без траты ячейки, восстанавливает заряд на продолжительном отдыхе. Поддерживает флаги прежних модулей `aindor-unique-items` и `bagryanaya-mantiya-echo`.
- **Прочный кожаный ремень:** надетый предмет типа `equipment` с точным названием «Прочный кожаный ремень» снижает текущую загруженность персонажа на 15 фунтов. Максимальная грузоподъёмность не изменяется.

## Установка

Foundry VTT → Модули → Установить модуль → URL манифеста:

`https://raw.githubusercontent.com/lipatosss/lipatos-aindor-unique-items/main/module.json`

Отключите прежние `aindor-unique-items` и `aindor-belt-weight`, чтобы не накладывать одну механику дважды. Уже существующие предметы удалять не нужно.

## Релизы

При изменении кода/манифеста workflow в GitHub Actions формирует ZIP, публикует его в GitHub Releases и обновляет архив указанной в манифесте версии.

## Вересковая медовуха (1.0.4)

После успешного использования расходуемого предмета с идентификатором `vereskovaya-medovuha` модуль применяет эффект «Вересковое тепло», бросает 1к4+1 и добавляет **одну пустую бутылку** (`pustaya-butylka`) в инвентарь использовавшего персонажа. При наличии бутылок их количество увеличивается на 1; дубликаты строк не создаются.

Шаблон бутылки ищется сначала в предметах мира, затем в инвентаре персонажей и доступных сборниках предметов. При наличии шаблона копируются исходная иконка, описание, цена (2 см), вес (0,5 фунта) и прочие настройки; шаблон не расходуется. Если шаблон отсутствует, создаётся предмет-добыча «Пустая бутылка» с запасной иконкой и выводится предупреждение. Действие на персонаже запускает один модуль: при включённых двух приоритет имеет «Баффы и дебаффы».

## Исправление 1.0.5: использование медовухи

- Убран ненадёжный WeakMap между `dnd5e.preUseActivity` и `dnd5e.postUseActivity`: D&D5e 6.x создаёт разные экземпляры Activity в начале и в конце использования.
- Обработка ведётся по успешному `dnd5e.postUseActivity` и его собственному объекту результата. Повторная доставка одного результата не создаёт второй бросок или бутылку.
- Списание заряда выполняется системой dnd5e; модуль больше не списывает его повторно. Если настройка `autoDestroy` включена, полностью израсходованная одиночная медовуха исчезает, а для стопки из нескольких бутылок уменьшается количество и сбрасывается счётчик зарядов.
- После применения «Верескового тепла» создаётся один предмет `pustaya-butylka` либо увеличивается его количество. При наличии исходного предмета мира сохраняются изображение и характеристики.

## Исправление 1.0.6: трата заряда не запускала баф

Для D&D5e v6.0.6 после реального списания заряда добавлен надёжный обработчик `updateItem` с проверкой `system.uses.spent`. Он самостоятельно запускает бросок `1d4+1`, эффект «Вересковое тепло» и возвращает `pustaya-butylka`, даже если `dnd5e.postUseActivity` не запустился. При штатной активности обработчик `postUseActivity` остаётся резервным, но один расход не может выдать две бутылки.

При `autoDestroy` полностью израсходованная медовуха удаляется. Оригинальная иконка бутылки берётся из предметов мира/сборника, если шаблон найден. Срабатывание действий доступно пользователю, который инициировал расход, и не повторяется на клиентах остальных игроков. Для диагностики откройте F12 и найдите сообщение «Вересковая медовуха: событие updateItem».

## Описание «Вересковое тепло» (1.0.7)

Описание эффекта сокращено: динамически выводится **результат последнего броска** временных хитов и преимущество против испуга на 1 час. Убраны мировое время и лишние строки. Сама механика медовухи не изменена.

## Кинжал рваной кромки (1.0.8)

При первом запуске версии 1.0.8 ГМ автоматически получает шаблон **«Кинжал рваной кромки»** в **Предметах мира**, если его там ещё нет. Предмет можно перенести в магазин Item Piles, персонажу или сборник и самостоятельно сменить иконку.

- **Идентификатор**: \`kinzhal-rvanoy-kromki\`; тип: оружие; немагический; редкость: необычное; цена: **90 зм**; вес: **1 фунт**.
- **База D&D 5e 2014**: кинжал, 1к4 колющего урона, фехтовальное, лёгкое, метательное (20/60 футов). Мастерство оружия 2024 не добавляется.
- **Рваная рана**: **один раз в свой ход**, при попадании по цели, которая **до атаки** уже потеряла хотя бы 1 хит и имеет больше 0 хитов, добавляется **1к4 колющего** к обычному броску урона. При критическом попадании кубик также удваивается по правилам 2014.
- **Использование**: сначала **назначьте ровно одну цель** (target token), затем сделайте бросок атаки кинжалом, после чего — обычный бросок урона. Модуль определит попадание по КД цели и добавит бонус, если выполнены условия. Без выбранной цели или доступа к её КД бонус не начисляется. Переброс урона сам по себе не создаёт повторный бонус.
- Не требуется макрос, добавочный видимый эффект, отдельный бросок или изменение параметров старых предметов.
- Использование за ход запоминается в флаге персонажа и сбрасывается естественно при смене хода боя. Вне боя бонус может срабатывать на каждую новую подходящую атаку (без понятия «ход»).

Для вручную созданного кинжала задайте \`system.identifier = "kinzhal-rvanoy-kromki"\` (или точное имя «Кинжал рваной кромки»). Текущие предметы не перезаписываются.

## Исправление Кинжала рваной кромки (1.0.9)

В dnd5e 6.x кнопка **Бросок урона** может использоваться без отдельного броска атаки. Раньше модуль игнорировал такой путь.
Теперь выберите **ровно одного раненого врага** целью (T) и нажмите **Бросок урона**: дополнительный 1к4 автоматически включается **в тот же бросок** и учитывает критический урон. Если был отдельный бросок атаки, бонус начисляется только после подтверждённого попадания, не после промаха. Если цель полна здоровья или имеет 0 хитов, бонус не срабатывает. Не чаще одного раза в свой ход в бою. Настроенные иконки и существующие предметы не изменяются.

После обновления перезапустите мир Foundry, обновите страницы (Ctrl+F5), заново откройте карточку кинжала и протестируйте бросок.

## Особые боеприпасы для магазина (v1.0.11)

Модуль создаёт два новых шаблона в **Предметах мира** при первом запуске активного ГМа (если они ещё не существуют). В существующих предметах и настраиваемых иконках ничего не меняется. Шаблоны переносятся в Item Piles вручную.

| Предмет | Идентификатор | Для оружия | Эффект | Цена за 1 | Вес за 1 |
| --- | --- | --- | --- | --- | --- |
| Стрела широкого наконечника | `strela-shirokogo-nakonechnika` | Короткий и длинный лук | +1 колющего урона | 2 зм | 0,05 фунта |
| Усиленный стальной болт | `usilennyy-stalnoy-bolt` | Арбалеты | +1 колющего урона | 2 зм | 0,075 фунта |

Оба боеприпаса немагические, не дают +1 к атаке. Реализованы нативно: `type: consumable`, `system.type.value: ammo`, `system.type.subtype: arrow/crossbowBolt`, `system.damage.base.bonus: '1'`, `system.damage.replace: false`, `magicalBonus: null`.

**Как использовать:** поместить боеприпасы в инвентарь стрелка, при броске **атаки** из лука/арбалета выбрать нужный боеприпас. Система dnd5e 6.x списывает **1 штуку после броска атаки**, а при броске урона добавляет отдельный +1 колющего урона. При 0 штук строка остаётся в инвентаре (autoDestroy=false), но не может использоваться для выстрела. Если сразу бросать **только урон** без атаки, система сама не списывает боеприпас, а бонус зависит от выбранного в карточке боеприпаса. Для корректного учёта расхода сначала бросайте атаку.

Бонус +1 фиксированный, при критическом попадании не удваивается. Бонусы луков и боеприпасов комбинируются. Например, «Лук тяжёлой тетивы» со специальной стрелой наносит 1к10 + модификатор Ловкости + 1 колющего урона.

Иконки пока стандартные запасные. Пользовательские иконки можно установить самостоятельно.

## Печать Последнего Дозора (v1.0.13)

При запуске активный ГМ получает готовый шаблон **«Печать Последнего Дозора»** в «Предметах мира» (только если такого предмета ещё нет). Иконка временная, существующие иконки и другие предметы не перезаписываются.

- **Идентификатор:** `pechat-poslednego-dozora`, тип `equipment`, очень редкий чудесный предмет, настройка обязательна, вес 0,5 фунта.
- **Надета и настроена:** штатный переносимый эффект +1 КД.
- **Рядом живой союзник (5 фт):** преимущество на спасброски против испуга, если в контексте броска явно указан испуг/страх/fear/fright. Проверка не распространяется на произвольные спасброски Мудрости.
- **Защитить союзника:** 1 раз до долгого отдыха, реакция, один общий заряд: (а) снизить урон видимому союзнику в 30 фт на `2к6 + бонус мастерства`, или (б) оставить союзника в 5 фт с 1 хитом при падении до 0 хитов.
- **Автоматизация:** при штатном получении урона `dnd5e.damageActor` у активного ГМа открывается окно выбора реакции; после подтверждения модуль бросает кости, восстанавливает соответствующие HP/временные HP и расходует заряд. При пропущенном окне выберите повреждённого союзника целью и нажмите действие предмета «Защитить союзника» в течение 60 секунд после урона.
- **Ограничения:** окно автоматической реакции отображается у активного ГМа (он согласует использование с владельцем). Для обработчиков повреждений, обходящих события `dnd5e.damageActor`, реакцию придётся запускать отдельно. Проверка видимости использует стены Foundry, когда доступен API; при недоступном API дополнительную проверку делает ГМ.

После обновления перезапустите мир Foundry и обновите клиентские страницы. Никаких макросов вручную создавать не нужно.


## Снаряжение ремесленников (v1.0.15)

При первом запуске ГМ автоматически получает в **Предметах мира** два шаблона без пользовательских иконок:

- **Кожанный фартух повара** (`kozhannyy-fartuh-povara`): одежда, 85 см, 2 фунта, необычный. При надевании **+1 к Кулинарии**.
- **Просмоленный кожанный костюм рыбака** (`prosmolennyy-kozhannyy-kostyum-rybaka`): одежда, 180 см, 5 фунтов, необычный. При надевании **+2 к Рыболовству**.

Бонусы учитываются модулем **LipatoS — Ремёсла v0.1.10+** при отображении ремесла и проверке к20. При снятии бонус исчезает, постоянные бонусы ГМа не изменяются. Одинаковые надетые предметы не суммируются. С бонусами от еды складываются. Можно заменить стандартные иконки вручную. У существующих предметов модуль иконки не заменяет.
